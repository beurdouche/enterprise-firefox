# Lockstore FFI (C++ Interface)

C++ Foreign Function Interface (FFI) for the Lockstore Rust library.

## Overview

The Lockstore FFI provides a C++ interface to the Lockstore secure storage system. It allows Firefox C++ code to store and retrieve encrypted data without needing to interact directly with Rust code. The FFI layer handles all the marshalling between C++ types (like `nsACString` and `nsTArray`) and Rust types, as well as managing the lifecycle of keystore and datastore instances.

The API is designed around a singleton pattern where a single keystore is opened for the browser session, and datastores are opened on-demand for specific collections. This simplifies resource management and ensures consistent state across the application.

## Architecture

The FFI layer provides C++ bindings organized into two functional areas:

- **Keystore Operations**: Manage the lifecycle of encryption keys. The keystore must be opened before any other operations. It stores the Key Encryption Key (KEK) and all Data Encryption Keys (DEKs). You create DEKs for collections here before you can store data in those collections.

- **Datastore Operations**: Perform CRUD operations on encrypted data. Each collection has its own datastore that handles encryption/decryption transparently. The datastore uses the DEK from the keystore to protect data.

The typical workflow is:
1. Open the keystore (once, at startup)
2. Create DEKs for any new collections
3. Open datastores for collections you need to access
4. Perform put/get/delete/list operations on datastores
5. Close the keystore when shutting down (this also closes all datastores)

## Header File

Include the generated header in your C++ code:

```cpp
#include "lockstore_ffi_generated.h"
```

This header is generated by cbindgen from the Rust FFI definitions and contains all function declarations, enum definitions, and type aliases needed to use the API.

## Enums

### LockstoreSecurityLevel

The security level determines how the DEK is protected. Currently, only local key encryption is supported:

```cpp
enum class LockstoreSecurityLevel : uint8_t {
    LocalKey = 0,
};
```

**LocalKey**: The DEK is encrypted using a locally-generated KEK. This provides encryption at rest - if someone copies the database files, they cannot decrypt the data without access to the keystore containing the KEK.

The cipher suite (AES-256-GCM) is selected automatically and is not exposed in the C++ API. This simplifies usage and ensures a secure default is always used.

## File Naming Convention

When you open the keystore with a profile path, the lockstore automatically creates database files using a standard naming convention:

- **Keystore**: `<profile_path>/lockstore.keys.sqlite` - Contains the KEK and all wrapped DEKs
- **Datastore**: `<profile_path>/lockstore.data.<collection>.sqlite` - Contains encrypted data for a specific collection

For example, with profile path `/home/user/.mozilla/firefox/abc123.default`:
- Keystore: `/home/user/.mozilla/firefox/abc123.default/lockstore.keys.sqlite`
- Logins datastore: `/home/user/.mozilla/firefox/abc123.default/lockstore.data.com.mozilla.logins.sqlite`

This convention means you only need to specify the profile path once when opening the keystore - all other paths are derived automatically.

## C++ Usage Examples

### Basic Setup and CRUD Operations

This example shows the complete workflow from opening the keystore to performing data operations. Note how the API only requires the collection name for most operations - paths are managed internally.

```cpp
#include "lockstore_ffi_generated.h"
#include "nsString.h"
#include "nsTArray.h"

// Open keystore with profile path
// This creates or opens the keystore database at <profilePath>/lockstore.keys.sqlite
nsAutoCString profilePath("/path/to/profile");
nsresult rv = lockstore_keystore_open(&profilePath);
if (NS_FAILED(rv)) {
    // Handle error - could be NS_ERROR_ALREADY_INITIALIZED if already open
    return rv;
}

// Create a DEK for a collection
// This generates a new encryption key for the "com.mozilla.logins" collection
// The key is wrapped (encrypted) with the KEK and stored in the keystore
nsAutoCString collection("com.mozilla.logins");
rv = lockstore_keystore_create_dek(
    &collection,
    LockstoreSecurityLevel::LocalKey
);
if (NS_FAILED(rv)) {
    // NS_ERROR_ALREADY_INITIALIZED means DEK already exists - often not an error
    return rv;
}

// Open datastore for the collection
// This creates or opens the data database and loads the DEK for encryption
rv = lockstore_datastore_open(&collection);
if (NS_FAILED(rv)) {
    // NS_ERROR_NOT_AVAILABLE means no DEK exists for this collection
    return rv;
}

// Store encrypted data
// The data is automatically encrypted with the collection's DEK before storage
nsAutoCString entryName("login_123");
const uint8_t* data = reinterpret_cast<const uint8_t*>("username:password");
size_t dataLen = strlen("username:password");
rv = lockstore_datastore_put(&collection, &entryName, data, dataLen);
if (NS_FAILED(rv)) {
    return rv;
}

// Retrieve data
// The data is automatically decrypted when retrieved
nsTArray<uint8_t> retrievedData;
rv = lockstore_datastore_get(&collection, &entryName, &retrievedData);
if (NS_FAILED(rv)) {
    // NS_ERROR_NOT_AVAILABLE means entry doesn't exist
    return rv;
}

// Use retrieved data - it's already decrypted
printf("Retrieved %zu bytes\n", retrievedData.Length());

// Delete an entry
// Returns whether the entry existed and was deleted
bool deleted = false;
rv = lockstore_datastore_delete(&collection, &entryName, &deleted);
if (NS_SUCCEEDED(rv) && deleted) {
    printf("Entry deleted successfully\n");
}

// Close datastore when done with this collection
rv = lockstore_datastore_close(&collection);

// Close keystore at shutdown - this also closes any open datastores
rv = lockstore_keystore_close();
```

### Multiple Collections

Applications often need to store different types of sensitive data. Each data type should use its own collection, which provides cryptographic isolation (each collection has its own DEK) and logical organization.

```cpp
#include "lockstore_ffi_generated.h"
#include "nsString.h"
#include "nsTArray.h"

nsAutoCString profilePath("/path/to/profile");

// Open keystore - this is done once for the entire application
nsresult rv = lockstore_keystore_open(&profilePath);
if (NS_FAILED(rv)) return rv;

// Create DEKs for multiple collections
// Each collection gets its own encryption key
nsAutoCString loginsCollection("com.mozilla.logins");
rv = lockstore_keystore_create_dek(
    &loginsCollection,
    LockstoreSecurityLevel::LocalKey
);
if (NS_FAILED(rv)) return rv;

nsAutoCString cookiesCollection("com.mozilla.cookies");
rv = lockstore_keystore_create_dek(
    &cookiesCollection,
    LockstoreSecurityLevel::LocalKey
);
if (NS_FAILED(rv)) return rv;

// Open datastores for each collection
// Each datastore operates independently with its own database file
rv = lockstore_datastore_open(&loginsCollection);
if (NS_FAILED(rv)) return rv;

rv = lockstore_datastore_open(&cookiesCollection);
if (NS_FAILED(rv)) return rv;

// Use each datastore independently
// Data in one collection cannot be decrypted with another collection's key
nsAutoCString user1Entry("user1");
const uint8_t* loginData = reinterpret_cast<const uint8_t*>("password");
rv = lockstore_datastore_put(
    &loginsCollection,
    &user1Entry,
    loginData,
    8
);

nsAutoCString sessionEntry("session");
const uint8_t* cookieData = reinterpret_cast<const uint8_t*>("session=abc");
rv = lockstore_datastore_put(
    &cookiesCollection,
    &sessionEntry,
    cookieData,
    11
);

// List all collections in keystore
// Useful for discovering what data exists or for migration
nsTArray<nsCString> collections;
rv = lockstore_keystore_list_collections(&collections);
if (NS_SUCCEEDED(rv)) {
    for (const auto& coll : collections) {
        printf("Collection: %s\n", coll.get());
    }
}
```

### Key Management

The keystore provides operations to manage the lifecycle of DEKs. This is useful for:
- Checking if a collection already has a DEK before creating one
- Listing all collections for administrative purposes
- Deleting DEKs when a collection is no longer needed

**Warning**: Deleting a DEK makes all data encrypted with that DEK permanently inaccessible. Always ensure the data is no longer needed or has been migrated before deleting a DEK.

```cpp
#include "lockstore_ffi_generated.h"
#include "nsString.h"
#include "nsTArray.h"

nsAutoCString profilePath("/path/to/profile");
nsresult rv = lockstore_keystore_open(&profilePath);
if (NS_FAILED(rv)) return rv;

// Create DEK - check for "already exists" case
nsAutoCString collection("com.mozilla.passwords");
rv = lockstore_keystore_create_dek(
    &collection,
    LockstoreSecurityLevel::LocalKey
);

if (rv == NS_ERROR_ALREADY_INITIALIZED) {
    // DEK already exists - this is often expected, not an error
    // The collection was set up in a previous session
    printf("DEK already exists for this collection\n");
}

// List all collections with DEKs
// Returns the collection names, not the keys themselves
nsTArray<nsCString> collections;
rv = lockstore_keystore_list_collections(&collections);
if (NS_SUCCEEDED(rv)) {
    printf("Found %zu collections:\n", collections.Length());
    for (const auto& coll : collections) {
        printf("  - %s\n", coll.get());
    }
}

// Delete a DEK - use with caution!
// This makes all data in the collection permanently inaccessible
bool deleted = false;
rv = lockstore_keystore_delete_dek(&collection, &deleted);
if (NS_SUCCEEDED(rv)) {
    if (deleted) {
        printf("DEK deleted successfully\n");
    } else {
        printf("DEK not found\n");
    }
}

// Close keystore
rv = lockstore_keystore_close();
```

### List Entries in a Collection

You can enumerate all entries in a collection without retrieving their data. This is useful for displaying lists to users, implementing search, or performing bulk operations.

```cpp
#include "lockstore_ffi_generated.h"
#include "nsString.h"
#include "nsTArray.h"

nsAutoCString profilePath("/path/to/profile");
nsAutoCString collection("com.mozilla.logins");

// Open keystore and datastore
nsresult rv = lockstore_keystore_open(&profilePath);
if (NS_FAILED(rv)) return rv;

rv = lockstore_datastore_open(&collection);
if (NS_FAILED(rv)) return rv;

// List all entries - returns entry names only, not the data
nsTArray<nsCString> entries;
rv = lockstore_datastore_list(&collection, &entries);
if (NS_SUCCEEDED(rv)) {
    printf("Found %zu entries:\n", entries.Length());
    for (const auto& entry : entries) {
        printf("  - %s\n", entry.get());
    }
}

// Retrieve each entry if needed
for (const auto& entryName : entries) {
    nsTArray<uint8_t> data;
    rv = lockstore_datastore_get(&collection, &entryName, &data);
    if (NS_SUCCEEDED(rv)) {
        printf("Entry '%s': %zu bytes\n", entryName.get(), data.Length());
    }
}
```

### Error Handling

Robust error handling is important for production code. The FFI uses standard Mozilla `nsresult` error codes, which allows consistent error handling patterns across the Firefox codebase.

```cpp
#include "lockstore_ffi_generated.h"
#include "nsString.h"
#include "nsTArray.h"

nsAutoCString profilePath("/path/to/profile");
nsAutoCString collection("com.mozilla.test");

// Open keystore first - required before any other operations
nsresult rv = lockstore_keystore_open(&profilePath);
if (NS_FAILED(rv)) {
    printf("Failed to open keystore: 0x%x\n", static_cast<uint32_t>(rv));
    return rv;
}

// Try to create a DEK
// Handle the "already exists" case gracefully - it's often not an error
rv = lockstore_keystore_create_dek(
    &collection,
    LockstoreSecurityLevel::LocalKey
);

if (rv == NS_ERROR_ALREADY_INITIALIZED) {
    // DEK exists from a previous session - this is OK
    printf("DEK already exists - continuing\n");
} else if (NS_FAILED(rv)) {
    printf("Failed to create DEK: 0x%x\n", static_cast<uint32_t>(rv));
}

// Open datastore - requires DEK to exist
rv = lockstore_datastore_open(&collection);
if (rv == NS_ERROR_NOT_AVAILABLE) {
    // No DEK for this collection - need to create one first
    printf("DEK does not exist for this collection\n");
    return rv;
} else if (NS_FAILED(rv)) {
    printf("Failed to open datastore: 0x%x\n", static_cast<uint32_t>(rv));
    return rv;
}

// Try to get a non-existent entry
// This is a normal case, not necessarily an error
nsAutoCString entryName("nonexistent");
nsTArray<uint8_t> data;

rv = lockstore_datastore_get(&collection, &entryName, &data);
if (rv == NS_ERROR_NOT_AVAILABLE) {
    // Entry doesn't exist - handle appropriately for your use case
    printf("Entry not found\n");
} else if (NS_FAILED(rv)) {
    printf("Failed to get entry: 0x%x\n", static_cast<uint32_t>(rv));
}
```

## API Reference

### Keystore Functions

These functions manage the keystore and its DEKs. The keystore must be opened before any other lockstore operations.

#### lockstore_keystore_open
```cpp
nsresult lockstore_keystore_open(const nsACString* profile_path);
```
Opens or creates the keystore database at `<profile_path>/lockstore.keys.sqlite`. This must be called before any other lockstore operations. If the keystore doesn't exist, it creates a new one and generates a KEK. If it already exists, it opens the existing keystore.

**Parameters:**
- `profile_path`: Path to the Firefox profile directory

**Returns:**
- `NS_OK`: Success
- `NS_ERROR_ALREADY_INITIALIZED`: Keystore is already open
- `NS_ERROR_FAILURE`: Database or cryptographic error

#### lockstore_keystore_create_dek
```cpp
nsresult lockstore_keystore_create_dek(
    const nsACString* collection,
    LockstoreSecurityLevel security_level
);
```
Creates a new Data Encryption Key (DEK) for a collection. The DEK is generated using NSS cryptographic primitives, wrapped (encrypted) with the KEK, and stored in the keystore. The cipher suite (AES-256-GCM) is selected automatically.

**Parameters:**
- `collection`: Name of the collection (e.g., "com.mozilla.logins")
- `security_level`: How the DEK should be protected (use `LockstoreSecurityLevel::LocalKey`)

**Returns:**
- `NS_OK`: DEK created successfully
- `NS_ERROR_ALREADY_INITIALIZED`: DEK already exists for this collection
- `NS_ERROR_NOT_AVAILABLE`: Keystore not opened

#### lockstore_keystore_delete_dek
```cpp
nsresult lockstore_keystore_delete_dek(
    const nsACString* collection,
    bool* ret_deleted
);
```
Deletes a DEK for a collection. **Warning**: This makes all data encrypted with this DEK permanently inaccessible. The associated datastore data should be deleted or migrated before calling this function.

**Parameters:**
- `collection`: Name of the collection
- `ret_deleted`: Output parameter set to true if a DEK was found and deleted

**Returns:**
- `NS_OK`: Operation completed (check `ret_deleted` for whether DEK existed)
- `NS_ERROR_NOT_AVAILABLE`: Keystore not opened

#### lockstore_keystore_list_collections
```cpp
nsresult lockstore_keystore_list_collections(
    nsTArray<nsCString>* ret_collections
);
```
Lists the names of all collections that have DEKs in the keystore. This does not return the keys themselves, only the collection names.

**Parameters:**
- `ret_collections`: Output array that will be populated with collection names

**Returns:**
- `NS_OK`: Success
- `NS_ERROR_NOT_AVAILABLE`: Keystore not opened

#### lockstore_keystore_close
```cpp
nsresult lockstore_keystore_close();
```
Closes the keystore and releases all resources. This also closes all open datastores. Call this when shutting down the application or when you no longer need lockstore access.

**Returns:**
- `NS_OK`: Success (or keystore was not open)

### Datastore Functions

These functions perform CRUD operations on encrypted data within a collection. A datastore must be opened before performing data operations, and the collection must have a DEK in the keystore.

#### lockstore_datastore_open
```cpp
nsresult lockstore_datastore_open(const nsACString* collection);
```
Opens or creates a datastore for a collection. The database is created at `<profile_path>/lockstore.data.<collection>.sqlite`. The function retrieves and unwraps the DEK from the keystore to enable encryption/decryption operations.

**Parameters:**
- `collection`: Name of the collection (must have a DEK in the keystore)

**Returns:**
- `NS_OK`: Success
- `NS_ERROR_NOT_AVAILABLE`: Keystore not opened, or no DEK exists for this collection
- `NS_ERROR_ALREADY_INITIALIZED`: Datastore is already open for this collection

#### lockstore_datastore_put
```cpp
nsresult lockstore_datastore_put(
    const nsACString* collection,
    const nsACString* entry_name,
    const uint8_t* data_ptr,
    size_t data_len
);
```
Stores data in the datastore. The data is automatically encrypted with the collection's DEK before being written to the database. If an entry with the same name already exists, it is overwritten.

**Parameters:**
- `collection`: Name of the collection
- `entry_name`: Unique identifier for this entry within the collection
- `data_ptr`: Pointer to the data to store
- `data_len`: Length of the data in bytes

**Returns:**
- `NS_OK`: Success
- `NS_ERROR_NOT_AVAILABLE`: Datastore not opened for this collection

#### lockstore_datastore_get
```cpp
nsresult lockstore_datastore_get(
    const nsACString* collection,
    const nsACString* entry_name,
    nsTArray<uint8_t>* ret_data
);
```
Retrieves and decrypts data from the datastore. The data is automatically decrypted using the collection's DEK.

**Parameters:**
- `collection`: Name of the collection
- `entry_name`: Identifier of the entry to retrieve
- `ret_data`: Output array that will be populated with the decrypted data

**Returns:**
- `NS_OK`: Success
- `NS_ERROR_NOT_AVAILABLE`: Datastore not opened, or entry doesn't exist

#### lockstore_datastore_delete
```cpp
nsresult lockstore_datastore_delete(
    const nsACString* collection,
    const nsACString* entry_name,
    bool* ret_deleted
);
```
Deletes an entry from the datastore.

**Parameters:**
- `collection`: Name of the collection
- `entry_name`: Identifier of the entry to delete
- `ret_deleted`: Output parameter set to true if the entry existed and was deleted

**Returns:**
- `NS_OK`: Operation completed (check `ret_deleted` for whether entry existed)
- `NS_ERROR_NOT_AVAILABLE`: Datastore not opened for this collection

#### lockstore_datastore_list
```cpp
nsresult lockstore_datastore_list(
    const nsACString* collection,
    nsTArray<nsCString>* ret_entries
);
```
Lists all entry names in a collection. This returns only the names, not the data itself. Use this to enumerate entries before retrieving them individually.

**Parameters:**
- `collection`: Name of the collection
- `ret_entries`: Output array that will be populated with entry names

**Returns:**
- `NS_OK`: Success
- `NS_ERROR_NOT_AVAILABLE`: Datastore not opened for this collection

#### lockstore_datastore_close
```cpp
nsresult lockstore_datastore_close(const nsACString* collection);
```
Closes a datastore and releases its resources. The datastore can be reopened later with `lockstore_datastore_open`. Note that `lockstore_keystore_close` automatically closes all open datastores.

**Parameters:**
- `collection`: Name of the collection

**Returns:**
- `NS_OK`: Success (or datastore was not open)

## Error Codes

The FFI uses standard Mozilla `nsresult` error codes:

| Error Code | Meaning |
|------------|---------|
| `NS_OK` | Operation succeeded |
| `NS_ERROR_FAILURE` | General failure (database error, cryptographic error, etc.) |
| `NS_ERROR_ALREADY_INITIALIZED` | Resource already exists or is already open. Returned when: keystore is already open, datastore is already open, or DEK already exists for a collection |
| `NS_ERROR_NOT_AVAILABLE` | Required resource not available. Returned when: keystore not opened, datastore not opened, DEK doesn't exist for collection, or entry doesn't exist |
| `NS_ERROR_INVALID_ARG` | Invalid arguments passed to function |

**Tip**: `NS_ERROR_ALREADY_INITIALIZED` when creating a DEK is often not an error - it means the DEK was created in a previous session. Handle this case gracefully by continuing with the existing DEK.

## Best Practices

1. **Always check return values**: Every FFI function returns an `nsresult`. Use `NS_SUCCEEDED()` and `NS_FAILED()` macros to check results.

2. **Open keystore at startup**: Call `lockstore_keystore_open` once when the application starts, not on each use. The keystore maintains state needed by all datastores.

3. **Create DEKs before datastores**: A collection must have a DEK before you can open its datastore. Handle `NS_ERROR_ALREADY_INITIALIZED` gracefully - it usually means the DEK exists from a previous session.

4. **Handle "not found" gracefully**: `NS_ERROR_NOT_AVAILABLE` when getting an entry is a normal case (entry doesn't exist), not necessarily an error condition.

5. **Close keystore at shutdown**: Call `lockstore_keystore_close` when the application exits. This cleans up all resources and closes all datastores automatically.

6. **Use descriptive collection names**: Follow reverse-DNS naming convention (e.g., "com.mozilla.logins") to avoid collisions and make the purpose clear.

## Thread Safety

The FFI layer is thread-safe. Internal registries use mutexes to protect concurrent access, so multiple threads can safely call these functions simultaneously. However, note that:

- The keystore and datastores use SQLite, which has its own concurrency model
- Rapid concurrent writes to the same entry may result in last-write-wins behavior
- For best performance, prefer batching operations rather than many small concurrent writes
